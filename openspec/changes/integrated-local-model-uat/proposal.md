# Proposal

## Why

The owner needs one persistent application using familiar Intervals.icu records and
a local model, not another synthetic demo or disconnected benchmark. The importer,
factual UI, contracts and confirmation boundaries exist, but normal personal model
execution is intentionally unwired; completed experiments do not close that gap.

## What Changes

- Deliver the first owner-UAT installation with **both app and model on the Mac**,
  as selected by the user on 2026-10-23. Run the app as an operator-installed private
  service with persistent storage, no demo deadline and no automatic data deletion.
  Availability requires the Mac to be awake and the user's service session running.
- Reuse the existing private Intervals credential and dashboard password files when
  their private validation succeeds. Metadata checks found both present, regular,
  nonempty and privately permissioned; contents, validity and current deployment
  compatibility have not been checked. Never request a token in chat.
- Complete three ordinary UI journeys: imported evidence to an explicitly requested
  descriptive model review; source note to editable extracted suggestions and explicit
  confirmation; an existing authored plan to a code-permitted amendment proposal and
  exact explicit approval. Initial model plan generation is not included.
- Add explicit, local-only **experimental owner-UAT admission**, distinct from model
  qualification and synthetic development permission. Ordinary production admission
  stays closed. Preserve strict whole-output validation, source binding, cancellation,
  resource supervision, private data handling and confirmation boundaries.
- Keep application lifetime unrestricted, but bound individual jobs. Propose one
  attempt, no correction/fallback, 900-second generation and 1200-second total job
  budget including a 60-second cleanup reserve. This is a new reviewed UAT policy,
  not a silent increase to existing 300-second personal limits. Sleep consumes elapsed
  budget; unavailable-host cleanup is reported uncertain until recovery stop proof,
  never falsely guaranteed at the deadline.
- Expose saved results and useful status directly in the app without requiring the
  owner to copy internal IDs. Allow on-request, content-free operational inspection;
  monitoring never imports, generates, approves changes or claims continuous agent
  supervision between requests.
- Consolidate old work honestly: reconcile and archive completed changes in dependency
  order; retain qualification, incompatible V2 work and deferred Pi verification as
  explicitly transferred/deferred obligations, never as passed tests. Preserve pending
  UI fixes and all frozen historical evidence.

## Capabilities

### New Capabilities

- `local-model-execution`: Private, supervised, owner-authorized execution of local
  model jobs with durable results, strict validation and bounded failure handling.

### Modified Capabilities

- `personalized-training-guidance`: Define an explicit experimental owner-UAT exception
  without claiming usefulness qualification; retain descriptive-only and exact plan
  approval boundaries. Reconcile the parent scoped-profile qualification requirement
  before applying this delta.
- `guidance-dashboard`: Persistent private Mac availability, three discoverable UAT
  journeys, honest unavailable/experimental states and non-mutating monitoring.

## Impact

Main backend admission, personal runtime control, execution routes and repositories;
local provider/prompt/schema adapters; intake and amendment integration; ordinary
frontend controls; a private Mac service/configuration/backup installation; existing
read-only Intervals import. Reuse the current executor and owned-runtime mechanics,
not a new scheduler, provider platform or synthetic launcher in the personal app.

The initial candidate is the already cached, pinned Qwen3:8b/Ollama runtime. Its last
small intake generation took about eight minutes; neither interactive latency nor
usefulness across all three personal profiles is accepted yet. No model download,
hosted transfer, Pi rollout, schema reset, automatic model schedule or autonomous plan
change is included.

**Planning only is currently approved.** Implementation needs an apply instruction.
Persistent service installation, personal-data import and real model execution require
their recorded operational checkpoints. The user's requested application has no
expiry; that does not remove authentication expiry or individual job safety limits.
